# Plan 01: Documentation Portal (SvelteKit) with the Quickstart Above the Fold

## 1. Goal

A dark, terminal-styled documentation site that a newcomer can go from landing
page to a running app in five minutes. Built with SvelteKit 2 and Svelte 5,
mdsvex for markdown pages, adapter-static for GitHub Pages, Pagefind for
client-side search.

Brand: Qt emerald `#2CDE85` on terminal navy `#0d1117`, monospace typography.

---

## 2. Location and Source of Truth

The site lives in **`website/`**, not `docs/`. `docs/` already holds migration
guides, architecture notes, benchmarks, and third-party notices, and a SvelteKit
project root with `node_modules` does not belong next to them.

There is exactly one source of truth for reference content, and it lives next
to the code:

| Content | Source location | Who writes it |
| :--- | :--- | :--- |
| C++ class reference | `src/Qtui/<module>/doc/*.md` (already exists) | Library authors |
| QML type reference | `docs/components/<type>.md` (new, one per type, Plan 04 template) | Library authors |
| Guides | `docs/guide/*.md` (new; absorbs `architecture.md`, `custom_items.md`, `qml_api.md`) | Library authors |
| Quickstart | `examples/quickstart/` (Plan 00) | CI-compiled code |
| Casts and images | `website/static/casts/`, `website/static/images/` (Plan 02) | Scripts |

The site never contains hand-written copies of these. A prebuild step copies
them in:

```json
{
  "scripts": {
    "prebuild": "node scripts/sync-content.mjs",
    "dev": "node scripts/sync-content.mjs && vite dev",
    "build": "vite build && pagefind --site build"
  }
}
```

`scripts/sync-content.mjs` copies `docs/components/*.md`, `docs/guide/*.md`,
`src/Qtui/**/doc/*.md`, and `examples/quickstart/*` into
`website/src/content/` (gitignored), rewriting relative links. Markdown files
carry frontmatter (`title`, `import`, `since`, `inherits`, `category`) that the
catalog page reads.

## 3. Directory Layout

```text
website/
├── package.json
├── svelte.config.js              # mdsvex + adapter-static, prerender all
├── vite.config.ts
├── scripts/sync-content.mjs
├── src/
│   ├── app.css                   # palette, code block theme
│   ├── lib/components/
│   │   ├── TerminalWindow.svelte # window chrome (Plan 02)
│   │   ├── AsciinemaPlayer.svelte
│   │   ├── ComponentCard.svelte
│   │   ├── CodeTabs.svelte       # CMakeLists / main.cpp / Main.qml tabs
│   │   └── SearchModal.svelte    # Pagefind
│   ├── content/                  # generated by sync-content, gitignored
│   └── routes/
│       ├── +layout.svelte        # nav, sidebar, dark theme
│       ├── +page.svelte          # landing: hero cast, pitch, quickstart
│       ├── guide/[slug]/+page.svelte
│       ├── components/+page.svelte        # catalog grid (31 cards)
│       ├── components/[slug]/+page.svelte # one QML type
│       ├── cpp/[slug]/+page.svelte        # one C++ class
│       ├── showcase/+page.svelte          # 8 apps, one story each
│       └── playground/+page.svelte        # Plan 05, hidden until ready
└── static/
    ├── casts/
    └── images/
```

Dynamic `[slug]` routes with `entries()` in `+page.ts` prerender one page per
markdown file, so adding a component doc never requires touching the site.

## 4. Landing Page, Top to Bottom

1. Hero: one looping cast of a flagship app (industrial_plc_hmi or btop) inside
   `TerminalWindow`. No text above it except the name and a one-line pitch.
2. Three-tab code block showing the quickstart files, read from
   `examples/quickstart/` so they are always the compiled versions.
3. The three commands:

   ```bash
   cmake -S . -B build
   cmake --build build
   ./build/hello_qtui
   ```

4. "Why Qtui": three short columns. Declarative QML vs immediate-mode Ratatui.
   Real `QAbstractItemModel` views. Headless `TestRunner` for CI.
5. Component catalog preview: six cards linking to `/components`.
6. Showcase preview: four app casts linking to `/showcase`.

## 6. Deployment (`.github/workflows/docs.yml`)

The previous draft passed `path` to `deploy-pages`, which does not accept it,
and lacked the permissions Pages requires. Corrected:

```yaml
name: Deploy Documentation
on:
  push:
    branches: [main]
    paths:
      - 'website/**'
      - 'docs/**'
      - 'src/Qtui/**/doc/**'
      - 'examples/quickstart/**'
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: 9
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm
          cache-dependency-path: website/pnpm-lock.yaml
      - run: pnpm install --frozen-lockfile
        working-directory: website
      - run: pnpm build
        working-directory: website
      - uses: actions/upload-pages-artifact@v3
        with:
          path: website/build

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

The `paths` filter includes the in-repo markdown so a doc edit next to the code
redeploys the site.

## 7. Acceptance

- `pnpm build` produces a fully prerendered site with zero SSR errors.
- Every `docs/components/*.md` file renders as a page and appears in the grid.
- The quickstart page shows byte-identical content to `examples/quickstart/`.
- Pagefind returns results for every QML type name and every property name.
- Lighthouse performance and accessibility both at or above 95 on the landing
  page.
